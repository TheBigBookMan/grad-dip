- a router or switch cannot operate without the need for an operating system
- the hardware has no functionality without an OS
- cisco IOS is th OS for cisco equipment
- foundational technology that underpins majority of ciscos offerings
- cisco IOS is used on all cisco equipment regardless of size or kind
- routers, LAN switches, tiny wireless access points, huge routers with hundreds of interfaces and other devices support this protocol
- **Introduction to Cisco IOS**-
	- delivers network services to devices
		- routing and switching operations at their most basic
		- access to networked resources that are both reliable and secure
		- scalability of the network
	- depending on the devices function and feature set, IOS operational specifics vary on different internetworking devices
	- cisco IOS serices often accessible via CLI and funtionalities abvailable through CLI differ depending on the IOS version and type of device
	- IOS data are many megabytes in size and stored on flash, a semipermanent memory space
	- non-valiatile storage is provided via flash memory which implies that when gadget loses power, the memory contents are not lost
	- while contents arent lost, they can be modified or overwritten if necessary
	- IOS may be updated to newer versions or new features can be introduced via flash memory
	- many router architectures copy IOS into RAM when device is turned on and the IOS runs from RAM when device in use

			- when the networking services have not been launched or have failed, the console port is frequently used to reach a device

				- procedures for disaster recovery and troubleshooting when remote access isnt possible

			- the connected computer may be used to submit configuration commands for setting up the router
			- if a router cannot be accessed remotely while in use, a connection to the console can be used to determine the devices status
			- the console displays device startup, debugging and error messages by default
		- **Telnet and SSH**-
			- telent to the router is one way across a CLI session remotely
			- telnet sessions, unlike console connections need active networking services on the device
			- at least one active interface on the networkdevice must be set with a layer 3 address like IPv4 address

			- telnet client is also included in IOS
			- **Virtual Teletype Interface (VTY)** sessions running on the cisco device can be accessed by a telnet client hiost

- **Configuration Files**-
	- network devices rely on two types of softwearte for their functioning: operating system and configuration software
	- the OS assists the fundamental operation of the device hardward components
	- cisco IOS software intructions that are needed to change the functioning of a cisco device are stored in configuration files
	- when system is booted (from startup-config gile) or when commands are input in the CLI while in configuration mode, the cisco IOS software parses the commands
	- configuration file can be kept remotely on a server as a backup
	- **Two Configuration Files onCisco device**-
		- **Startup Configuration File**
			- when the device is turned on, the backup configuration is loaded
			- the beginning file system (startup-config) is being used to set up the device at system startup
			- the startup configuration file is kept in non-volatile memory (NVRAM)
			- becue NVRAM is non-volatile the file remains intact after the cisco device is switched off
			- the startup-config files are loaded into RAM when the router is launched or reloaded
			- the running configuration, is the configuration file that has been put into RAM
		- **Running Configuration File**-
			- during the devices current functioning, this parameter is used
			- running-config is used to operate the network device once loaded into RAM
			- when a network administrator configures a device, the operating configuration is changed
			- changes to the operating configuration immediately impact the ciscos devices functionality
			- after making any modifications, the administrator can save them to the startup-config file which will ensure that they are utilised the next time the device rebtoots
			- because the running configuration file is stored in RAM, it will be lost if the device is switched off or restarded
			- if changes to the running-config file ar enot saved tro the startup-config file before the device is turned off, they will be lost

- **Banner Messages**-
	- one approach to keep unauthorised users out of a network, its also critical to give a mechanism to declare that only authorised users should attempt to obtain access to the device
	- banners output does this
	- because everyone attempting to login can view banners the message must be crafted well
	- the days message is a typical banner (MOTD) because it is shown on all linked terminals, it is utilised for legal notice
	- to identify content of the banner message, the **banner motd** command requires delimiters
	- a space and a delimiting character after the **banner motd** command
	- banner message is then represented by one or more lines of text
	- the end of the message is indicated by a second appearance of the delimiting letter
	- any letter can be used as the delimitting character provided it does not appear in the message
	- as a result, symbols like # are often utilised
		- `Switch(config)# banner motd # message #`
